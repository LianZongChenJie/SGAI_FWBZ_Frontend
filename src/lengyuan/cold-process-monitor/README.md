# 冷源运行工艺监控

沿用现有智慧园区运行监控页面框架，依据 `HVAC拓扑图-new.pptx` 建立水蓄冷工艺图。冷水机组、冷却塔、水泵和分集水器复用原工程 2.5D 设备素材，换热器、阀门、水处理器和水箱采用可交互的立体 SVG。管道使用多层管壁、高光和投影表示厚度，交叉留白与实心汇合点区分连通关系。

## 打开方式

直接双击 `index.html` 可查看 PPT 参考数据、放大工艺图、点击设备以及查看控制点位，不需要安装依赖。

实时数据服务需要 Node.js 18 或以上版本，在本目录运行：

```powershell
node server.mjs
```

打开 http://127.0.0.1:8812 ，点击“切换实时接入”。启动服务不会自动读取任何现场设备，未推送点位显示 `—`。环境变量 `PORT` 可修改端口。

本交付包为独立冷源工艺模块，移除了依赖原工程的“平面监测”跳转。所有页面、素材和脚本均包含在包内。

## 工艺范围

- 冷水机组 3 台、冷却塔 3 台、换热器 3 台。
- 冷却泵、放冷泵、蓄冷泵、冷冻泵分别 3 台，补水泵 1 台。
- 编号阀门 21 个：VD1–VD15、VD17–VD22。原图没有 VD16，不自行补号。
- 分集水器旁通阀与浮球阀各 1 个，分水器、集水器、补水箱、蓄冷池各 1 个。
- 软水器 1 个、全程水处理器 2 个、冷量表 3 个、系统参数对象 1 个。
- 总计 **56 个设备及监控对象、155 条管段、420 个点位，其中控制点位 93 个**。24 个测温点归属蓄冷池。泵组共用电表归属系统对象，并在相应水泵弹窗显示，不复制为单泵电量。

设备目录可搜索名称或编号。点击设备后，在“监测参数”“控制点位”页查看相应字段。蓄冷池另有“分层温度”页。图例可以聚焦介质；“＋”“−”“总览”“全屏”用于查看大画布。小屏幕允许横纵滚动。

## 数据依据与待核对事项

工艺连接依据 PPT 第1页，设定参数依据第2页，电缆温度依据第1、4页，电表和冷量表字段依据第6页。第10页为通讯拓扑，没有足够信息确定每个点的寄存器地址。

所有现场地址保留为空。PPT 参考数值不会被标成实时值；工程预留点没有虚构默认值。VD7 开度 118.5% 和室外湿度 118.5% 保留原图读数并提示超量程。电表负累计值、部分冷量表异常温度没有作为正常监测默认值采用。蓄冷池“冷量”原图单位为 kW，保留并标注“原图单位”，实际能量单位需核对。

一次水系统包括冷机、放冷泵、蓄冷泵、换热器一次侧和蓄冷池。双向支路表示工况切换，实际阀门动作、一次侧 A/B 口在不同工况下的流向、蓄冷池上下布水器接口关系应结合现场图纸和 PLC 程序确认。箭头只表达设计流向，不把历史截图解释为实时流量。

本版本展示控制点位，不向 PLC 下发启停、模式或设定值。上线写入需要正式点表及权限、白名单、范围、联锁和操作记录适配。

## 文件

- `index.html`、`platform.css`：平台框架与入口。
- `process.css`、`app.js`：2.5D 工艺、设备弹窗、状态、交互和接入。
- `data.js`：设备、端口、连接、介质、点位、出处和参考默认值。
- `model.js`：统一数据校验、质量码和过期处理。
- `server.mjs`：HTTP / WebSocket 服务，不依赖第三方包。
- `assets/`：复用的立体设备 PNG 素材。
- `接口说明.md`、`拓扑核对.md`：接入和拓扑资料。

## 验证

已检查 56 个设备的实际点击与控制标签页、点位唯一性及默认值、端口引用、正交管段、对象和数组点位更新、非法批次原子拒绝、WebSocket 推送、定向动效、过期状态，以及 1280×720、1440×900、1920×1080 的布局和弹窗边界。浏览器未发现脚本错误。静态页面不需要编译，使用 Node 语法检查和实际运行检查验证。
